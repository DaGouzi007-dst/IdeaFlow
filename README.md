# IdeaFlow

软件工程课程项目：跨 AI 会话的想法整理、来源追溯与任务跟踪。

## 项目介绍

使用多个 AI 工具讨论和开发项目时，相关内容容易分散在不同会话中。IdeaFlow 将以网页应用的形式集中管理会话，支持内容检索、想法整理，并记录方案选择、任务进度和执行结果。

## 计划实现的主要功能

1. **会话导入与管理**：导入会话、统一数据格式，按项目组织和查看。
2. **内容检索与来源追溯**：搜索历史内容，定位原始会话和具体消息。
3. **想法提取与整理**：保存和编辑想法卡片，分类整理并保留原文出处；后续评估 AI 辅助提取和关系提示。
4. **决策与任务跟踪（ProgressGate）**：记录方案采用理由、任务状态、阻塞原因和处理结果。

第一阶段计划跑通：创建项目 → 导入会话 → 搜索并查看原文 → 保存想法卡片 → 创建任务 → 更新状态和结果。

## 协作约定

- 每位成员使用自己的 GitHub 账号和提交身份，及时提交自己的工作成果。
- 分工确定后，各模块在同一项目框架和数据约定下开发，并定期集成。
- 每周记录进展、障碍、关键决策及理由、AI 建议的采纳或拒绝依据，以及下周计划。
- 不提交账号密钥、真实私密会话、依赖目录和无关大文件；导入测试优先使用脱敏或模拟数据。
- 每周提交给助教的仓库压缩包须包含 `.git` 目录，命名为“组号-第n周-代码仓库.zip”。不要用 GitHub 的 Download ZIP 代替完整 Git 仓库打包。

## 技术方案与运行方式

第四模块当前使用 Vue 3 + JavaScript + Vite、Python + FastAPI + SQLModel、SQLite，可按 [模块说明](progressgate/README.md)独立运行。这是已实现演示的技术选择，不表示全组接口、部署和权限方案均已确认。

运行 `python scripts/check_delivery.py` 可只读检查本分支材料、正式分支历史及不应提交的文件。该命令不会打包、推送或运行其他成员代码，不能代替模块测试与全组验收。本地开发工具另存的快照不属于正式交付范围；未来打包需从已确认分支制作干净 Git 副本，并保留副本的 `.git`。
