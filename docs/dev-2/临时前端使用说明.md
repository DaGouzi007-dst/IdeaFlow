# 检索验证页（临时前端）

## 用途

用于在浏览器中验证第二部分"搜得到、看得懂、能回到原文"核心链路：
输入关键词 → 查看结果卡片（片段高亮 + 会话 + 来源工具）→ 点击跳回原文并定位高亮。

**不是正式前端**：无构建、无路由、无组件化，只用于功能验证和演示。总前端整合后可删除。

## 文件位置

```
backend/
├── static/
│   └── index.html      ← 验证页（单文件，原生 JS）
└── app.py              ← 需包含静态挂载配置
```

`app.py` 的挂载配置：

```python
from pathlib import Path
from fastapi.staticfiles import StaticFiles

_static = Path(__file__).parent / "static"
_static.mkdir(exist_ok=True)
app.mount("/", StaticFiles(directory=_static, html=True), name="static")  # 必须在 include_router 之后
```

**顺序要求**：`mount("/")` 兜底所有未匹配路径，必须放在 `app.include_router(router)` 之后，否则 `/api/*` 会被静态文件拦截。

## 启动

```bash
cd backend

# 1. 准备数据（二选一）
python -m container
# 或导入第一部分样例：
# python -c "from container import init_from_aggregate; init_from_aggregate('../docs/样例/跨模块样例数据.json')"

# 2. 启动服务
uvicorn app:app --reload
```

浏览器打开 **http://127.0.0.1:8000** 即为验证页。

## 使用

| 操作 | 说明 |
|---|---|
| 输入关键词 + 回车 / 点"搜索" | 调用 `POST /api/search` |
| 项目 ID 输入框 | 可空；填写则按项目过滤 |
| 工具复选框 | 不勾 = 全部；勾选则按来源工具过滤 |
| 结果卡片 | 显示工具徽标、会话标题、日期、角色、高亮片段 |
| 点击卡片 | 新标签打开查看器，自动滚动到目标消息并高亮片段 |

## 验证清单

按顺序操作，全部符合预期即链路成立：

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 搜 `JWT` | 3 条，跨不同工具，`JWT` 高亮 |
| 2 | 项目填 `P1` 再搜 `JWT` | 2 条 |
| 3 | 清空项目，只勾 `Claude` 搜 `Redis` | 0 条，显示空态提示 |
| 4 | 搜 `幂等` | 1 条，`幂等` 两个字**整体**高亮（不拆成两个单字） |
| 5 | 点击该结果 | 新标签打开，滚到目标消息，片段黄色高亮 |
| 6 | 搜 `blockchain` | 0 条，空态 |
| 7 | 搜 `缓存击穿` | **只高亮「缓存击穿」四个字**，不再单独高亮「做缓存」里的「缓存」；emoji 不导致错位 |
| 8 | 搜 `订单 状态机` | **≥1 条**（AND 无结果，自动降级为 OR；改前为 0 条） |
| 9 | 搜 `状态机 幂等` | 仍 1 条 S2-m2（AND 有结果，**不**降级） |
| 10 | 搜 `JWT` 并勾 `Claude` | 0 条（降级不绕过工具筛选） |

**重点说明**

- 第 4 条验证**区间合并**：jieba 把「幂等」切成「幂」+「等」，后端已合并为一段，前端应看到一个整体高亮。
- 第 7 条验证**短语优先**：整串「缓存击穿」能连续匹配时只标这一处，不再逐词标「缓存」。
- 第 8 条验证**降级触发**：AND 无结果时自动走 OR，返回包含任一词的消息。
- 第 9 条验证**降级不误触发**：AND 有结果时绝不走 OR，结果集与改前一致。
- 第 10 条验证**筛选不被绕过**：降级时 `tools`、`projectId` 等筛选条件原样保留。

**第 5 条是核心链路**，同时验证检索 → `SourceRef` → 深链 → 查看器四个环节。

## 注意事项

1. **数据来源**：页面显示的是 `search.db` 当前内容。跑 `python -m container` 为 12 条测试数据；跑 `init_from_aggregate` 为第一部分样例。`rebuild` 是全量替换，两者不共存。
2. **工作目录**：必须在 `backend/` 下启动，`search.db` 才会生成/读取在同一位置。
3. **高亮偏移**：后端返回 Unicode 码点偏移，页面内 `cpSlice` 函数做 UTF-16 换算，**总前端复用时必须保留这一层**。
4. **高亮粒度**：单查询串能连续匹配时只高亮整串（如「缓存击穿」只标四个字）；多词查询（带空格）或连续匹配不到时，退化为逐词高亮。相邻/重叠的区间已由后端 `_merge_ranges` 合并，**前端按返回的 `highlights` 数组直接画 `<mark>` 即可，不要自己再按关键词拆分**。
5. **多词查询降级**：搜多个词时，若没有消息同时包含全部词，后端自动降级为「包含任一词」并返回结果。当前页面**仅结果数量变化，未显示「已放宽匹配」的提示**——`SearchResult.relaxed` 字段已预留，前端可据此加一行提示。
6. **不做的事**：无分页 UI、无工具动态列表、无错误重试、无响应式。这些留给总前端。

## 与总前端的关系

临时页只用于验证，整合后删除。**交给总前端复用的是以下四项**：

- `index.html` 中的 `cpSlice` / `renderSnippet` 高亮函数（码点 → UTF-16 换算）
- **高亮行为约定**：后端返回的 `highlights` 已合并相邻区间；短语查询返回单区间，多词查询返回多区间。前端按区间画 `<mark>` 即可，**不要自己再按关键词拆分**
- **降级提示**：`SearchResult.relaxed === true` 表示「AND 无结果，已放宽为 OR」，建议前端显示一行提示，如「未找到同时包含全部关键词的消息，已为你显示包含任一词的结果」
- 一页《前端对接说明》：`/api/search` 请求响应示例、`SearchHit` 字段渲染映射、深链拼法

页面本身的 HTML/CSS 无需保留。
