## 一、搜索接口（前端）

### 1.1 `POST /api/search`

**请求体**

```json
{
  "q": "缓存击穿",
  "projectId": "P1",
  "sessionIds": ["S2"],
  "tools": ["Claude"],
  "roles": ["user", "assistant"],
  "page": 1,
  "pageSize": 20,
  "mode": "keyword"
}
```

字段说明

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `q` | string | ✅ | 查询词，支持多词（空格分隔） |
| `projectId` | string | ⭕ | 项目过滤 |
| `sessionIds` | string[] | ⭕ | 会话过滤 |
| `tools` | string[] | ⭕ | 来源工具过滤（如 `ChatGPT` / `Claude` / `Cursor`） |
| `roles` | string[] | ⭕ | 角色过滤（`user` / `assistant` / `system`） |
| `page` | int | ⭕ | 从 1 开始，默认 1 |
| `pageSize` | int | ⭕ | 默认 20 |
| `mode` | string | ⭕ | 当前仅 `keyword` 生效，`semantic` / `hybrid` 为预留 |

**响应体**

```json
{
  "hits": [
    {
      "ref": {
        "projectId": "P1",
        "sessionId": "S1",
        "messageId": "S1-m4",
        "charStart": 9,
        "charEnd": 13,
        "snippet": "Redis 做缓存，注意缓存击穿：热点 key 过期瞬间大量请求打库。😀"
      },
      "sessionTitle": "数据库选型讨论",
      "tool": "ChatGPT",
      "role": "assistant",
      "createdAt": "2024-05-10T10:05:00+08:00",
      "snippet": "Redis 做缓存，注意缓存击穿：热点 key 过期瞬间大量请求打库。😀",
      "highlights": [[11, 15]],
      "score": 3.42,
      "matchedBy": "keyword"
    }
  ],
  "total": 1,
  "page": 1,
  "tookMs": 12,
  "relaxed": false
}
```

#### `highlights` 语义（本周更新）

`highlights` 是相对 `snippet` 的**码点区间**数组，已由后端处理完毕：

| 场景 | 返回行为 |
|---|---|
| 分词切碎（如“幂等”切成“幂”+“等”） | 相邻区间**已合并**为一段，返回 `[(7,9)]` 而非 `[(7,8),(8,9)]` |
| 短语查询（整串在原文连续匹配，如“缓存击穿”） | 只返回**一个**区间，只高亮整串 |
| 多词查询（带空格，如“订单 状态机”）或整串连续匹配不到 | 返回**多个**区间，逐词高亮 |

**前端实现要求**：

- 直接按 `highlights` 数组画 `<mark>`，**不要自己按关键词拆分或合并**
- 按**码点**切片（不是 UTF-16），JS 中需用 `Array.from(str).slice(a, b)` 或等价的码点遍历，示例函数见下

```javascript
function cpSlice(str, a, b) {
  return Array.from(str).slice(a, b).join('');
}

function renderSnippet(snippet, highlights) {
  const cps = Array.from(snippet);
  if (!highlights?.length) return escapeHtml(snippet);
  let out = '', last = 0;
  for (const [a, b] of highlights) {
    if (a > last) out += escapeHtml(cps.slice(last, a).join(''));
    out += '<mark>' + escapeHtml(cps.slice(a, b).join('')) + '</mark>';
    last = b;
  }
  if (last < cps.length) out += escapeHtml(cps.slice(last).join(''));
  return out;
}
```

#### `relaxed` 字段（本周新增）

| 值 | 含义 |
|---|---|
| `false` 或缺省 | 正常匹配，结果均含全部关键词 |
| `true` | **多词查询无 AND 结果，已自动放宽为 OR**，结果只保证含任一词 |

**前端实现要求**：`relaxed === true` 时显示提示，避免用户困惑：

> 未找到同时包含全部关键词的消息，已为你显示包含任一词的结果。

#### `ref` 字段用途

`ref` 是 `SourceRef` 的完整坐标，前端用于：

- 生成跳转链接：调 `GET /api/trace/link?projectId=&sessionId=&messageId=&charStart=&charEnd=`，或按既定格式手拼
- 传给第三部分（若用户在搜索结果里“建想法卡片”，直接存这个 `ref`）
- 调 `GET /api/trace/resolve` 取原文

### 1.2 `GET /api/tools`

**用途**：返回索引中出现过的来源工具及条数，供前端动态渲染筛选项（临时验证页已使用）。

**请求**：无参数。

**响应**：

```json
[
  {"tool": "Doubao", "count": 10},
  {"tool": "DeepSeek", "count": 4}
]
```

**说明**

- 按条数倒序；`tool` 为空的记录不计入
- 前端应据此生成复选框，不要在页面里写死平台名（否则新增平台要改代码）
- 当前 `tool` 取值来自数据源：第一模块导入时为 `source`（`synthetic` 等导入渠道），插件导出时为 `platform`（`Doubao` / `DeepSeek`）

## 二、溯源接口（第三部分）

本节接口**本周无变更**，签名与返回结构保持稳定。

### 2.1 `SourceRef` 契约

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `projectId` | string | ✅ | 项目 ID |
| `sessionId` | string | ✅ | 会话 ID |
| `messageId` | string | ✅ | 消息 ID，第一模块导入时生成的 UUID；离线样例缺失 id 时才用 `{sessionId}-m{seq}` 兜底 |
| `charStart` | int \| null | ⭕ | 片段起始（Unicode 码点） |
| `charEnd` | int \| null | ⭕ | 片段结束 |
| `snippet` | string \| null | ⭕ | 引用时的原文片段，用于漂移检测和兜底展示 |

**序列化约定**：两端统一走 Pydantic，不要手拼 JSON。

```python
# 写入（第三部分）
source_ref = SourceRef(...).model_dump_json(by_alias=True)   # camelCase JSON
quote = ref.snippet

# 读出（调第二部分前）
ref = SourceRef.model_validate_json(row.source_ref)
```

### 2.2 `GET /api/trace/resolve`

**用途**：单条出处解析。

**入参**：`SourceRef` 的字段作为 query 参数。

**返回**：`ResolvedSource` 或 `null`。

```json
{
  "ref": { "projectId": "P1", "sessionId": "S2", "messageId": "S2-m2",
           "charStart": 0, "charEnd": 4, "snippet": "用状态机" },
  "sessionTitle": "订单状态机设计",
  "message": { "id": "S2-m2", "content": "用状态机，注意幂等…", "...": "..." },
  "excerpt": "用状态机",
  "available": true,
  "precision": "exact"
}
```

**`precision` 语义**：

| 值 | 含义 | 前端渲染 |
|---|---|---|
| `exact` | 有偏移且片段校验通过 | 正常高亮 `excerpt` |
| `message_only` | 无偏移，或片段已漂移 | 定位到整条消息，不做高亮，提示“原文位置可能已变化” |

**返回 `null` 与 `available=false` 的区别**：

- `null`：消息不存在（已被删除）
- `available=false`：消息存在，但片段内容已变更（漂移）

### 2.3 `POST /api/trace/resolve-batch`

**用途**：批量解析，第三部分列表页用。

**请求体**

```json
{
  "refs": [ { "projectId": "P1", "sessionId": "S2", "messageId": "S2-m2",
              "charStart": 0, "charEnd": 4, "snippet": "用状态机" } ],
  "includeContext": false
}
```

**响应**

```json
[
  {
    "messageId": "S2-m2",
    "status": "ok",
    "resolved": { "ref": {...}, "excerpt": "用状态机", "precision": "exact", "available": true }
  },
  { "messageId": "XX-m1", "status": "missing" }
]
```

**`status` 三态**：

| 值 | 含义 |
|---|---|
| `ok` | 消息存在且片段可用 |
| `drifted` | 消息存在但片段已变更 |
| `missing` | 消息不存在 |

**注意**：`includeContext=true` 时每条结果附 `context` 字段（前后各 1 条），数据量约三倍，**仅详情页用，列表页关闭**。

### 2.4 `GET /api/trace/context`

**用途**：取出处前后各 N 条消息。

**入参**：`projectId`、`sessionId`、`messageId`、`before`（默认 2）、`after`（默认 2）。

**返回**：`{ center, before[], after[], sessionId }`。

### 2.5 `GET /api/trace/link`

**用途**：生成跳转 URL。

**返回**：`{ "link": "/viewer/projects/P1/sessions/S2?msg=S2-m2&hl=0-4" }`。

**注意**：`link` 是**相对本服务**的路径，调用方必须用自己配置的 base 前缀拼接（如 `PART2_BASE`），不要假定是绝对 URL。

第 1 部分正式会话页就绪后，`link` 的前缀会切换，调用方**不要自己拼 URL**，统一用此接口。

### 2.6 渲染决策表

| `status` / 返回情况 | 第三部分应如何展示 |
|---|---|
| `ok` + `precision=exact` | 展示 `excerpt` 并高亮，跳转带 `hl` |
| `ok` + `precision=message_only` | 展示 `excerpt` 或 `quote`，跳转只滚到消息，不做高亮 |
| `drifted` | 展示本地 `quote`，提示“出处内容已更新” |
| `missing` 或 `resolve` 返回 `null` | 只展示本地 `quote`，禁用跳转，提示“原始会话已删除” |

## 三、对接注意事项

### 3.1 给前端

1. **高亮用 `highlights`，不要自己分词**：后端已合并区间、已处理短语优先，前端直接画 `<mark>`
2. **按码点切片**：`charStart` / `charEnd` 是 Unicode 码点偏移，JS 需用 `Array.from` 遍历，否则 emoji 会错位
3. **处理 `relaxed`**：为 `true` 时显示“已放宽匹配”提示
4. **跳转不要手拼 URL**：统一调 `GET /api/trace/link`
5. **`mode` 字段当前只支持 `keyword`**：传 `semantic` 会退化为关键词检索，无报错

### 3.2 给第三部分

1. **`message_id` 必须与第一模块一致**：由第一模块导入时生成 UUID，全链路沿用同一编号；第二部分不再自造 `{conversation_id}-m{seq}`（仅离线样例缺失 id 时兜底）。不一致则 `resolve` 返回 `null`  (11.22更新)
2. **服务端口**：本模块固定监听 `8002`；第三部分用 `PART2_BASE`（默认 `http://127.0.0.1:8002`）调用 `/api/trace/link`，换端口需同步设置该环境变量。
3. **`source_ref` 用 Pydantic 序列化**：`SourceRef.model_dump_json(by_alias=True)`
4. **`quote` 不可为空**：作为原文失效时的兜底
5. **批量优先**：列表页用 `resolve-batch`，不要循环调 `resolve`

### 3.3 已知限制

| 项 | 现状 |
|---|---|
| 语义检索 | `Retriever` 端口已预留，`mode='semantic'` 尚未实现，传了也走关键词 |
| 停用词过滤 | 未做，搜“那缓存用什么”会命中“那”“用”等噪音词 |
| 分页 `total` | 当前 `total` 是召回集大小，非全库匹配数 |
