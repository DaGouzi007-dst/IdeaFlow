# 决策与任务跟踪模块：第一阶段需求分析

负责人：唐逸飞。整理日期：2026 年 11 月 1 日。本文是 IdeaFlow 小组需求分析中第四模块的可合并章节，不代替完整项目的需求分析报告；课程作业模板公布后还需统一格式。

## 1. 问题与范围

在整理出想法之后，项目参与者需要区分“讨论过”“决定采纳”和“正在执行”，并在执行受阻时保留原因、尝试过程及处理结果。模块目标是记录这些状态及关联，方便继续推进和回顾。

第一阶段实现决策记录、任务创建、任务更新、阻塞与结果记录、任务变更历史。项目、想法、会话和原始消息由其他模块负责；当前用共同样例替代这些输入。

本阶段采用人工填写与确认。系统不会根据 AI 的一段建议直接判定团队已经采用方案，也不会从任务状态推断代码已完成或测试已通过。自动发现阻塞、自动恢复执行和跨工具实时接入不属于当前完成范围。

## 2. 参与者与前置条件

主要参与者为项目参与者，可查看想法、记录决定、创建和更新任务。负责人目前是可空姓名文本，不是用户账号；本地演示不提供登录或基于角色的权限控制。

使用前需要存在项目。关联想法创建任务还需要该想法属于同一项目，且其当前决策为已采纳。手动任务允许不关联想法。

## 3. 核心用例

### UC-PG-01：记录想法决策

用户选中想法，设置待讨论、已采纳或暂不采纳，并可填写理由；保存后可再次读取和修改。同一想法至多有一条当前决策，更新沿用原决策编号。当前不保存每次决策修改的历史版本。

想法不存在时返回明确错误。记录决策不会自动创建任务，也不会改变已有任务。

### UC-PG-02：创建任务

用户填写标题，可补充任务说明、负责人、截止日期和完成条件；可手动创建，也可选择已经采纳的同项目想法。系统生成任务编号，初始状态为待开始，并产生一条创建记录。

空白标题、无效日期、未知项目、跨项目想法和未采纳的关联想法不能创建成功。失败时不应留下任务或任务创建记录。

### UC-PG-03：更新进展并记录阻塞

用户选择任务，修改状态或补充执行信息后保存。状态包括待开始、进行中、受阻和已完成。系统校验保存后的整体状态：受阻必须存在阻塞原因，已完成必须存在执行结果。

遇到问题时可补充错误片段、已尝试的方法和下一步；解决后填写处理结果并更新状态。恢复进行中不清除原有阻塞记录，便于回顾。当前允许用户根据实际情况重新调整状态，不实施额外的单向状态限制。

### UC-PG-04：回顾任务变更

用户查看任务的进展记录，可以看到创建及字段修改的时间、修改前后内容。重复保存相同内容不额外产生变更记录。只保存任务的当前值不能代替历史记录。

### UC-PG-05：查看关联及来源

用户可以从任务打开关联想法，在想法中查看相关任务；有来源时可查看来源消息及上下文。手动任务或手动想法没有来源时，应显示无关联状态。

当前来源展示读取模拟数据，属于独立演示。真实原文定位和搜索结果由检索、会话及想法模块共同提供。

## 4. 领域对象与职责

- **Decision（决策）**：维护 `decision_id`、`project_id`、`idea_id`、采用状态、理由和更新时间；负责表达当前选择，不承担任务执行。
- **Task（任务）**：维护 `task_id`、所属项目、可空的关联想法、标题、说明、负责人、日期、完成条件、状态、阻塞信息和执行结果；负责承载当前执行情况。
- **TaskEvent（任务事件）**：维护事件编号、任务编号、事件类型、字段变化和创建时间；一个任务可对应多条事件。
- **Project / Idea / 来源消息**：是本模块依赖的外部领域对象；使用共同编号关联，不在本模块另建一套真实会话或想法管理功能。

内部编号使用 UUID 字符串；修改内容不更换编号。一个想法可以形成多项任务；一项任务目前至多关联一个想法。数据库暂不建立指向其他模块真实表的外键，当前关联检查由样例访问及应用逻辑完成，集成时需共同确定。

## 5. 接口边界

已实现的本模块接口：

- `GET` / `PUT /api/ideas/{idea_id}/decision`：读取或保存当前决策。
- `GET` / `POST /api/projects/{project_id}/tasks`：查询或创建任务。
- `GET` / `PATCH /api/tasks/{task_id}`：查看或更新任务。
- `GET /api/tasks/{task_id}/events`：查询任务变更。

临时样例接口：

- `GET /api/projects`、`GET /api/projects/{project_id}/ideas`。
- `GET /api/demo/ideas/{idea_id}/sources`。

临时样例接口不是替其他成员完成的正式接口。运行后可在后端 `/docs` 查看实际请求体、响应和参数约束。

## 6. 非功能要求与验收

决策、任务和任务事件使用本地 SQLite 保存；关闭连接后重新打开仍能读取。输入需要限制长度、检查状态枚举和日期，错误信息能够帮助用户修正填写内容。

第一阶段验收场景为：采纳一个模拟想法并保存理由；创建关联任务和手动任务；记录一次受阻、恢复和完成；查看历史与关联；重新打开数据库确认记录保留。具体结果见 [第一阶段验证记录](../testing/ProgressGate-第一阶段验证记录.md)。

## 7. 后续协作事项

需要与其他模块确认真实项目和想法接口、来源返回结构、错误约定、共享数据表和数据库迁移方案。替换样例后才能验证完整项目流程。正式页面还需要把布局、配色及组件规范与其他成员统一；独立功能页面和设计原型目前是两套实现。
