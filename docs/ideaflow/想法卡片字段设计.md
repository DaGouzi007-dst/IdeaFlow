# 想法卡片设计

这个文档作为前期part3开发的核心设计文档，规定基本数据结构与功能设计，第一版demo将会基于此进行开发。

模块 3 把对话里有用的内容整理成想法卡片，并记录它的出处和与其他卡片的关系。

## 一、表结构

三张表：`idea` 是卡片本身，`idea_source` 记录卡片来自哪条消息，`idea_relation` 记录卡片之间的关系。

### idea

| 字段 | 说明 | 类型 | 必填 |
|---|---|---|---|
| idea_id | 编号 | UUID | 是 |
| project_id | 所属项目 | UUID | 是 |
| title | 标题 | 文本，不超过 200 字 | 是 |
| summary | 一句话说明或备注 | 文本 | 否 |
| tags | 标签，逗号分隔 | 文本 | 否 |
| premise | 适用条件，即这条建议在什么前提下成立 | 文本 | 否 |
| stage | 现在做 / 以后再说 / 已放弃 | 枚举 | 是 |
| favorite | 收藏 | 布尔 | 是 |
| created_at | 创建时间 | 带时区的 ISO 8601 | 是 |
| updated_at | 最后修改时间 | 带时区的 ISO 8601 | 是 |

列表默认按“收藏 + 更新时间”倒序排列，所以除新建外，其余写操作都要更新 `updated_at`。

### idea_source

| 字段 | 说明 | 必填 |
|---|---|---|
| idea_id | 想法编号 | 是 |
| message_id | 来源消息编号，由模块 1 生成 | 是 |
| source_ref | 外部工具的原始编号 | 否 |
| quote | 引用原文 | 否 |
| created_at | 关联时间 | 是 |

主键为 `(idea_id, message_id)`，同一条想法可以关联多条消息，同一条消息也可以被多条想法引用。

### idea_relation

| 字段 | 说明 | 必填 |
|---|---|---|
| relation_id | 关系编号 | 是 |
| from_idea_id | 想法 A | 是 |
| to_idea_id | 想法 B | 是 |
| relation_type | 重复 / 互补 / 冲突 | 是 |
| confidence | 系统建议的置信度，0~1 | 否 |
| status | 待确认 / 已确认 / 已拒绝 | 是 |
| note | 判定理由 | 否 |
| created_at | 创建时间 | 是 |
| updated_at | 修改时间 | 是 |

约束：`from_idea_id` 与 `to_idea_id` 不能相同；同一对卡片同一类型的关系只能有一条，写入时按编号从小到大存，避免存重复。

## 二、几点说明

- 出处单独建表。一条想法可能来自多条消息，而且消息删除后要靠 `quote` 显示原文，字符串拼编号做不到。
- `summary` 只保留一个字段，列表里显示一行，详情里显示一段。
- 标签暂用逗号分隔，等需要按标签统计或改名时再拆表。
- 采纳状态（待讨论 / 已采纳 / 暂不采用）由模块 4 的决策记录，这里不重复保存。
- 关系是对称的，只存一条，查询时两边都查。

## 三、边界情况

- 删除卡片时，同时删除它的来源记录和关系记录。
- 来源消息被删除，关联记录保留，页面显示“来源不可用”，原文用 `quote` 代替。
- 允许手动创建没有出处的卡片。
- 重复标记同一关系时返回 409；撤销只改关系状态，不删除卡片。
